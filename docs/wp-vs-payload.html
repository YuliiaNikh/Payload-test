Can Payload replace our WordPress stack?

Our sites run on WordPress with Elementor or Gutenberg, JetEngine, WPML, Yoast and HubSpot forms. This page compares each part with Payload CMS 3 (on Next.js) and marks what is built in, what needs a plugin, and what we would build ourselves.

Payload 3.93 · Next.js 16Languages tested: EN + HE (RTL)Updated 13 Nov 2026 · demo live

Summary

Short version: Payload covers the content model, languages, workflow and security better than our WP stack. What it does not give out of the box is a drag-and-drop canvas and ready-made filter/listing widgets. Those become our own reusable code, built once in a starter kit.

Strong

  • Fields, CPTs and relations (ACF + JetEngine relations) in typed code
  • Field-level translation, per-language layouts and slugs (WPML)
  • Drafts, autosave, live preview, scheduling, revisions with diff
  • No plugin marketplace to break or get hacked
  • Fast pages by default (server rendering, CDN cache)

We build once

  • Block library from Figma (our "widgets")
  • Listing block with filters (JetEngine listings + JetSmartFilters)
  • Dynamic visibility, open to any condition we add
  • Mega menu, multiple headers and footers
  • Sitemap, hreflang, schema, language switcher

Watch out

  • No on-canvas drag and drop. Editing is a form beside a live preview
  • Clients cannot install plugins. New features need a developer
  • Team needs TypeScript and React, not PHP
  • Hosting needs Node + Postgres, not shared WP hosting
  • No built-in translation jobs or Yoast-style readability score

Decisions needed

These are open on purpose. The demo implements the recommended option and keeps the others possible.

1. How do clients build new sections from Figma?

  1. A. Layered (recommended for the demo). Developers build ready-made section blocks from Figma. Clients also get a few flexible layout blocks (columns, rich text, image, buttons) for simple new sections.
  2. B. Ready-made blocks only. Every new design is a developer task. Most consistent design, least client freedom.
  3. C. Free nested builder. Section → columns → widgets, like Elementor. Most freedom, and the same risk of broken layouts we want to leave behind.

Open question: how much layout freedom each client tier gets, and whether a new Figma section is included in support or billed.

2. Forms: HubSpot embed or Payload form builder?

  1. HubSpot embed (demo). Same as today. The client builds forms in HubSpot.
  2. Payload form builder plugin. Forms and entries live in the CMS, with emails, and are sent to the CRM through a hook. Works for clients without HubSpot.

3. Hosting per client

  1. Vercel + Neon Postgres + Vercel Blob (this demo). Zero server work. Vercel Hobby is non-commercial, so client sites need a paid plan.
  2. Our own VPS or cloud with Docker. Payload runs anywhere Node runs. More control and predictable cost, but we maintain servers.

To be reviewed by the backend team: hosting, database, storage, backups, security and costs.

4. Translation help

  1. Manual + "Copy to locale" (demo). Editors copy the English page into Hebrew and translate.
  2. AI translate button (Claude API) that fills the Hebrew fields for review. Not in the demo; easy to add later.

Client walkthroughs

What an editor does in the Payload admin. Each flow works on the demo site.

Create a page

  1. Pages → Create new, choose a template (Blank, Landing, About, Contact, Archive).
  2. The page fills with that template's sections.
  3. Edit text and images in the form; the live preview on the right updates as you type.
  4. Add sections with "Add block", drag to reorder, or paste a block copied from another page.
  5. Set header and footer in Page appearance, fill the SEO tab.
  6. Save draft, share a preview link, then Publish or schedule it.

Translate a page

  1. Open the page and switch the language selector to Hebrew.
  2. Use Copy to locale to bring over the English sections, or start empty for a different Hebrew layout.
  3. Translate texts, swap images, set the Hebrew slug.
  4. Preview shows the page right-to-left.
  5. Publish Hebrew. English stays as it is, and each language shows its own status.

Add a menu item

  1. Headers → Main header → Menu.
  2. Add an item: Link, Dropdown or Mega menu.
  3. For a link, pick the page from a list. It keeps working if the page slug changes.
  4. For a mega menu, add columns, links with descriptions, an optional promo card or an automatic "latest posts" column.
  5. Switch to Hebrew to edit the Hebrew menu, which can be different.
  6. Save and publish.

What we learned building it

Findings from building the demo in one day with Payload 3.93 and Next.js 16.

Per-language publishing works

Payload's experimental per-locale status kept English-only pages out of Hebrew and hid drafts correctly. Every front-end query must filter on "published" explicitly; otherwise unpublished languages come back as empty drafts.

Database names hit Postgres limits

Deeply nested blocks produce table names over 63 characters. Short field names or a dbName fix it; worth a convention in the starter kit.

Migrations are large but safe

Each block exists per collection in the database, so the block library migration had ~400 tables. Every migration was rehearsed on an empty and an upgraded copy before deploy; none lost data.

Live preview refreshes on save

Blocks render on the server, so the preview updates on every autosave (about 2 seconds), not per keystroke.

Scheduling needs a cron

Scheduled publish runs from a job queue. On the Vercel Hobby plan the cron can only run daily; per-minute scheduling needs Pro (or our own server).

Share links are coarse

A preview link turns on draft mode for that browser, so it shows drafts of other pages too until "Exit preview". Fine for clients, not for secrets.

No caching yet

Pages render on each request (fast enough for the demo). Production sites should add per-page caching with refresh on publish.

Testing pays off

~100 unit/integration tests and ~34 browser tests run against a local database; they caught real bugs (filter logic, slug-change loops, a header label shared between languages).
